# Existing workflows and this project's scope

Primary-source review, 2026-10-04. This is a bounded portfolio build, not a novelty, patentability, unique-market-position or validated-demand claim.

| Existing option | Documented capability | MergePanel's narrower role |
| --- | --- | --- |
| [Adobe Data Merge](https://helpx.adobe.com/indesign/desktop/automation-and-scripting/merge-data/merge-records.html) | Native single/multiple-record merging with layout-specific constraints | Prepare one wide data row for an existing fixed-slot template; preserve a source-to-slot receipt |
| [EasyCatalog](https://www.65bit.com/docs/easycatalog-demonstration-files/) | Per-record/per-group objects, group headers, record tables and native pagination modes | Portable CSV preparation without operating the design application |
| [MyDataMerge](https://mydatamerge.com/wizards/tutorial/?sel=14017%2C13848%2C14686%2C14638%2C17666%2C14539) | Prepared groups for multiple records, arranged merge order and front/back examples | A small local recipe and auditable placement packet for bounded fixed-capacity work |

MyDataMerge's first-party tutorial was corroborated through its indexed source content; direct access was blocked during this review. It was not installed or tested. Group-aware publishing tools already exist. We do not imply otherwise.

## Useful difference

The project combines exact grouping, stable field tokens, explicit padding presence, header-based source updates, a reversible source-to-slot manifest and a visible multiline policy. It produces a data handoff, not a native layout engine. This can be useful when a designer already has a repeated-slot template and wants to inspect how a spreadsheet was regrouped before importing it.

The included workshop table has interleaved groups. At capacity three it generates two Make records and one Share record, with two padding slots. The output deliberately collects groups, and the manifest makes that global reorder inspectable.

## Compatibility boundary

The current [Adobe source-file documentation](https://helpx.adobe.com/indesign/desktop/automation-and-scripting/merge-data/data-source-files-overview.html) gives contradictory multiline guidance in different sections. That supports an explicit conservative policy, not an unconditional statement about application support. Generic CSV preserves parsed values; an optional text-only replacement produces a receipt. Paths and identity values stay exact.

The [field-binding documentation](https://helpx.adobe.com/indesign/desktop/automation-and-scripting/merge-data/add-and-edit-data-fields.html) describes the image marker and actual Data Merge field insertion. Generated headers follow that documented shape. Native import, image resolution, output pages and overset still need a named-version test with an actual template.

## Deferred deliberately

No INDD/IDML editing, variable geometry, native application automation, linked-asset packaging, duplex imposition, conditional frame removal, dynamic field formulas, extra grouping levels, data joins, server accounts or publication. There is no evidence yet of user demand or willingness to pay.
